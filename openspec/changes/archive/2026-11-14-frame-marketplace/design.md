# Design

## Context

行程规划主线完成后第一条创收路径（动机见 proposal.md）。现状约束：
- 系统已有 owner 鉴权（`get_current_user`）、事件流（`TripEvent` + `event_service`）、journey 投影（`journey_service`）、LLM 双路径先例（`xhs_service` / `story_service`）、打卡数据（`Stop.checked`）
- 无任何支付/订单/文件存储基础设施——一期用兑换码模式绕开支付闭环
- 站点趣事复用 `Stop.description`（受邀者已可编辑该字段）；当日一句话总结复用已有 `TripDay.note`（journey 投影已作 day 主题使用），不新增字段
- 完整业务设计（含已批准的方案对比）见 `docs/superpowers/specs/2026-11-12-frame-marketplace-design.md`

## Goals / Non-Goals

**Goals:**
- 兑换码 → 权益 → 模板解锁的最小可信商业闭环（可对账、防重放、幂等）
- 单日卡 + 整程总结图的数据投影与 AI 配文（LLM 主路径 + 模板兜底）
- 前端 Canvas 渲染器：照片不出设备、风格化轨迹、未购水印预览
- 免费 2 套 + 付费 2 包各 3 套的种子模板目录

**Non-Goals:**
- 支付直连/订单系统、退款、权益过期（资质就绪后二期演进）
- 照片云端存储、模板后台热更新、自动发布到任何社媒平台
- 高清印刷纪念册（后端 Pillow 方案 A 的演进方向，本期不做）

## Decisions

1. **前端 Canvas 渲染（方案 B），照片仅内存处理**——隐私红线与卖点；无需文件存储基础设施；导出一致性与设备分辨率绑定是可接受的代价。备选方案 A（后端 Pillow + 照片上传）被否决：上传/存储/清理管线 + 隐私顾虑，工作量大。后端不下发渲染素材，权益绕过无实质风险。
2. **兑换码只存 SHA-256 哈希**——数据库泄露也无法伪造/复用；明文由一次性脚本 `scripts/gen_codes.py` 输出供上架后即弃。备选（明文 + 校验字段）被否决：泄露面大。
3. **权益模型 = (user_id, pack_slug) 唯一约束 + 幂等兑换**——同一用户重放自己的码返回 200 已解锁；他人已用返回 409；未命中 404；吊销 410。不建订单表，兑换记录即权益记录。
4. **模板 = 前端可执行 JSON 配置 + 后端种子目录**——模板元数据（slug/tier/theme/layout_config）在后端，渲染逻辑在前端 `templates.js` 注册表按 slug 对齐；新增模板发版即可，无需后台。
5. **轨迹不嵌地图瓦片，用坐标手绘风格化路线**——Leaflet/高德瓦片有 CORS 限制无法导出成图；站点坐标球面投影 → 虚线 + 编号节点 + 地名标签，手账风格与相框审美契合，且零外部依赖。
6. **配文复用 xhs 双路径架构**——`frame_copy_service.py` 参照 `story_service`：LLM 主路径 + 规则模板兜底 + source 诚实标注；最终兜底为用户趣事原文 + 固定话题。channel=xhs/moments。
7. **数据投影与渲染分离**——`/frames/{day_id}/data` 只出结构化投影（仅 checked 站点，owner 限定），前端渲染器消费；与 journey 投影同一「空数据诚实返回」哲学（空投影 → 入口置灰）。

## Risks / Trade-offs

- [兑换码被暴力枚举] → 码空间足够大（随机 ≥12 位）、限速沿用现有配额服务模式、明文不落库
- [用户 A 的码被 B 兑换] → 这是合法场景（码即资产），权益只解锁兑换者本人；spec 已覆盖
- [前端渲染各浏览器差异] → 导出固定 1242×1656 + DPR 感知；纯函数部分（布局/投影/换行）vitest 单测兜底
- [LLM 配文质量不稳定] → 双路径降级链保证永远有产出；source 诚实标注
- [付费模板前端可被绕过] → 渲染在前端理论上可被调试绕过；接受（模板为数字轻资产，水印 + 后续服务端高清导出可收紧）
