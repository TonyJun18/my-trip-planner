# 当 AI 旅行工具都在抢着替你花钱：独立规划层的生存策略

> 写给：AI 行程/规划类产品的产品经理和工程师，以及想在 AI 旅行赛道找差异化的小团队。
> 一句话结论：2026 年下半年，AI 旅行赛道的主流玩家正在集体「向上够预订层」——做 agentic 机票、agentic 酒店、被 OTA 并购。这不是独立工具该跟的牌局。独立工具的生存策略不是「更努力地做预订」，而是**把规划层做深到预订层玩家不愿做、也做不好的程度**：免费、透明、可修订、可协作、可自托管。

## 一、先看 2026 年 7 月这个月

两个行业事件几乎同时发生，把「AI 旅行赛道正在变成预订漏斗」这件事拍在了桌上：

**1. Mindtrip 上线 Mindtrip Stays（2026-07）。** 继 2026-05 推出"行业首个 agentic 机票预订"（Sabre Mosaic 库存 + PayPal 聊天内结账）后，Mindtrip 又上线了 agentic 酒店搜索与预订——用户可以在对话里直接完成"查酒店 → 比价 → 下单"。加上与 Minneapolis、San Diego、Boston 等 DMO（目的地营销组织）的合作，Mindtrip 的商业重心已经很明确：**发现与预订，而不是深度规划**。与之对应，评测多次指出它"实际行程物流细节弱"——餐厅、交通衔接这类规划层细节，常常要追问才给。

**2. Expedia Group 收购 Layla（2026-07-31 官方 IR 公告）。** 对话式 AI 旅行代理 Layla（含家族产品 TripPlanner AI）并入 Expedia，成为其"AI 原生规划 + 预订"战略的一部分。Layla 的招牌是实时定价（Skyscanner/Booking）、PriceLock 锁价、8M+ 行程——它走的是"免费规划引流 → 预订/服务收费"的漏斗，现在连漏斗本身都进了 OTA。

把时间线再拉长一点：**Tripnotes.ai 停运（2026 确认）**。曾经靠 ChatGPT 行程规划病毒式传播的明星产品，被 Dorsia（会员制餐厅预订）收购后关站，创始团队转去做高端餐厅预订。

三条新闻拼在一起是完整的信号：**AI 旅行赛道的资本和产能正在向"可预订"集中。** 规划是入口，订机票/酒店/活动才是商业闭环。Mindtrip 自己做预订、Layla 被 OTA 收编、Tripnotes 直接关站——独立小工具想靠"生成行程"本身活下来，越来越难。

## 二、预订层是重资产，规划层是轻资产

把 AI 旅行产品按商业模型拆成两层，差异一目了然：

| 维度 | 规划层（Plan） | 预订层（Book） |
|---|---|---|
| 核心资产 | 行程生成、修订、质检、协作 | 实时库存/票务、支付、价格预测 |
| 数据要求 | POI/天气/距离（开放或低成本） | 航司/酒店 GDS、实时价格、退改规则 |
| 信任成本 | 中（错了用户自己改） | 高（订错了要赔） |
| 履约 | 无（用户自行决定） | 有（支付、出票、售后、客服） |
| 典型玩家 | 我们、Wanderlog、Stippl、MonkeyTravel | Hopper、Layla/Expedia、Mindtrip |
| 小团队可行性 | ✅ 可行 | ❌ 极难（重资产、合规、资金） |

Hopper 是预订层的极端样本：靠价格预测（AI 说"现在买还是等"）积累 1 亿用户，再用增值付费变现——护城河是多年票务数据，独立团队短期内不可能复制。

**所以独立工具的正解是：把规划层做深，而不是向上够预订层。** 规划层的"深"不是多生成几种行程模板，而是四件事：**可修订、可验证、可协作、可自托管**——这四件事预订层玩家天然不愿做（改行程动了他们的库存和佣金），也做不好（预订闭环的组织复杂度决定了规划只能做入口）。

## 三、我们怎么把规划层做深：四根支柱

我们（my-trip-planner，FastAPI + LangGraph + Vue3，开源于 github.com/TonyJun18/my-trip-planner）没有做任何预订功能，全部资源压在规划层的四根支柱上。以下代码引用均与仓库实际一致（main 分支）。

### 支柱一：可修订——AI 出 diff，代码执行

预订层产品怕用户改（改了要重算价格库存），规划层产品应该**欢迎用户改**。我们把"改行程"做成一等公民：

```python
# backend/app/services/revise_service.py
async def revise_trip(db, trip_id, message, *, owner=None, provider="auto"):
    # 1) AI 只生成结构化 diff（PlanReviseAgent，无工具、失败可自纠正）
    revise = await plan_revise_agent({...}, current_plan, provider=provider)
    # 2) 代码原子应用（存在性/类型/位置校验，任一失败整体回滚）
    _apply_diff(trip, diff)
    # 3) 落库 + 预算代码重算（LLM 估值不可信）
    await _recompute_budget(db, trip)
    await db.commit()
```

用户说"第三天西湖改成半天，晚上加楼外楼"，AI 产出 `{op, target, fields}` 指令集，**代码**负责执行——意图可信、行为可校验、失败可回滚。这是所有竞品里唯一带回滚保障的修订路径。修订在这里是产品差异化的核心，不是事后补丁。

### 支柱二：可验证——价格真实度与质检闭环

规划层最容易被骂"假大空"的就是预算和推荐质量。我们用两条路对抗：

**价格真实度**：酒店参考价用代码确定性估算，不靠 LLM 瞎报：

```python
# backend/app/services/budget_service.py
def estimate_hotel_cost(name, city=None, *, rating=None) -> float:
    base = _HOTEL_CITY_BASE.get(_match_city(city), _HOTEL_FALLBACK)  # 城市基准价
    multiplier = 1.0
    for kw, m in _HOTEL_TIER:            # "五星"×2.8、"经济"×0.7 ……
        if kw in name:
            multiplier = m
            break
    ...
```

城市基准价 × 档位倍率 × 评分修正——**可解释、可测试、不依赖外部价格源**，前端标注"参考价，以实际询价为准"。我们不会假装"帮你订到最便宜的酒店"，但我们保证预算不是空壳。

**质检闭环**：Planner 产出后由 `TravelCriticAgent`（无工具质检专家）按日程/预算/地理/完整性四维评分，不过审带反馈重生成（最多 2 轮后强制定稿，质检失败自动降级放行）。配合前端实时 T-A-O（Thought-Action-Observation）轨迹（`frontend/src/views/PlanWizard.vue` 的"查看 AI 专家协作过程"面板），**用户能看到每个 Agent 在干什么、为什么这么生成**——黑盒是规划层最大的信任杀手，透明是免费工具最便宜的护城河。

### 支柱三：可协作——把多人决策留在规划层

多人出行是高频刚需，但群组共编 (co-edit) 复杂度高。我们做轻量协作：分享链接 + 评论 + 站点 👍/👎 投票（凭 share_token 免登录、投票幂等可翻转、同行程归属校验）：

```python
# backend/app/services/collab_service.py
async def _belongs_to_trip(db, stop_id, trip_id) -> Stop:
    """校验站点属于该行程（防止跨行程投票）。"""
    stmt = (select(Stop).join(TripDay, TripDay.id == Stop.id)
            .where(Stop.day_id == day_id, TripDay.trip_id == trip_id))
    ...
```

一行 `share_token` + 一组轻接口，就把"群里十个链接来回发"变成"一个链接大家投票定行程"——规划层的协作不需要拼实时协同编辑，先把决策问题解决。更近一步，分享链接还支持「受邀编辑权」（edit_token 与只读 share_token 分离，受邀者可改站点顺序/备注/勾选，owner 可收回），把"规划是大家一起定的"这件事做到位<sup>注：受邀编辑权为 2026-09-24 在途分支能力（nightly/2026-09-24/2-task-share-edit），合并 main 后生效</sup>。

### 支柱四：可自托管——开源是规划层的天然护城河

预订层永远无法开源（库存、价格、支付都是商业机密）。规划层可以。我们把整个仓库 MIT 开源，用户自己 `docker compose up` 就能跑起来——没有账号墙、没有数据锁定、没有"你的行程是别人家的流量"。对独立开发者和小团队来说，**开源不是情怀，是把"透明"这个规划层优势资本化**：预订层玩家被商业模型锁死不能做的事，我们天然能做。

## 四、可复用的模式

| 决策 | 落地方式 | 收益 |
|---|---|---|
| 不做预订闭环 | 只做规划层（生成/修订/质检/协作/自托管） | 避开重资产，专注体验 |
| 价格用代码估算 | 城市基准价 × 档位倍率（budget_service） | 可解释、可测试、无外部依赖 |
| 修订走 diff + 原子应用 | AI 出指令、代码执行（revise_service） | 可信、可回滚、可解释 |
| 质检做成闭环 | TravelCritic 四维评审 ≤2 轮（graph） | 输出质量有闸门，不无限烧 token |
| 协作做轻量版 | share_token + 评论 + 投票 + 受邀编辑权（collab_service） | 多人决策可闭环，不碰协同编辑复杂度 |
| 透明做资本化 | MIT 开源 + T-A-O 轨迹 + 参考价标注 | 预订层玩家锁死不能做，我们天然能做 |

**最关键的迁移心态**：先想清楚你的产品在哪一层。如果你在规划层，就把"修订、验证、协作、透明"做到竞品做不到的深度；如果决定做预订层，请准备好库存、支付、客服和资金——那不是小团队用 prompt 能补齐的。

## 五、给用户的一份「规划层工具清单」

如果你不想被 AI 旅行工具"顺手把机票也订了"，可以用这些独立规划工具（2026-09 时点）：

- **my-trip-planner**（本仓库）：开源、可自托管、diff 修订 + 质检 trace + 城市基准价透明估算。
- **Wanderlog**：手动规划 + 地图 + 实时协作最强，AI 在付费墙内（Pro $39.99/年）。
- **Wonderplan**：纯免费、极低门槛、PDF 导出，功能较薄。
- **MonkeyTravel**：免登录 + 群组投票引擎，多语言，不碰预订。

选择标准就一条：**它是否尊重"你自己决定"**——能不能改、改完给不给看、数据带不带走。

## 小结

- 2026 年下半年，AI 旅行赛道的主流正在集体转向预订层：Mindtrip 做 agentic 机票/酒店，Layla 并入 Expedia，Tripnotes 关站。
- 预订层是重资产（库存/支付/售后/客服），独立工具的正解是把规划层做深：**可修订（diff+原子应用）、可验证（价格估算+质检闭环）、可协作（轻量投票+受邀编辑）、可自托管（开源）**。
- 规划层不是"等被收购的过渡形态"——免费、透明、可自托管本身就是长期差异化；预订层玩家被商业模型锁死做不了的事，正是规划层工具最该做深的事。
