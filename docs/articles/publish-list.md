## 二、三篇文章发布卡片（可直接复制）

### 文章① 多 Agent 编排不是堆 Agent

- **标题**：多 Agent 编排不是堆 Agent：单一职责 + 并行采集 + 编排层补位
- **摘要**：很多人做的"多 Agent"其实是一个超长 prompt + 一个循环。本文用真实项目（FastAPI + LangGraph 智能行程规划）讲清楚：多 Agent 到底拆什么、并行什么、用什么兜底——职责拆分（每个 Agent 一件事）、并行采集（asyncio.gather）、编排层代码补位（LLM 不做的事交给代码）。
- **标签**：多Agent、LangGraph、FastAPI、AI工程、后端
- **平台**：掘金（首发）/ 知乎 / 公众号

### 文章② 让 Agent 稳定输出

- **标题**：让 Agent 稳定输出：Pydantic 强校验 + 失败自纠正
- **摘要**：LLM 不是 API，是"概率性 JSON 生成器"。本文用真实代码讲：怎么让 Agent 稳定产出结构化 JSON，失败了自己改对——Pydantic Schema 强校验、错误摘要回喂 LLM 自纠正（最多 3 次）、三层兜底（上限/截断/迭代上限）。**LLM 输出不可信，schema 才可信。**
- **标签**：Pydantic、结构化输出、LLM工程、AI Agent
- **平台**：掘金 / 知乎

### 文章③ Agent 的容错工程

- **标题**：Agent 的容错工程：重试、熔断、降级，以及 FakeLLM 测试
- **摘要**：Agent 系统对外部依赖（LLM API、搜索、天气）的失败处理，决定了它是 demo 还是产品。四件事：指数退避重试（只重试瞬时错误）、滑动窗口熔断（拒绝撞墙）、多源降级（高德→Tavily/wttr.in）、FakeLLM 测试替身（不耗 token、可进 CI）。
- **标签**：容错、熔断、重试、可测试性、AI工程
- **平台**：掘金 / 知乎 / 公众号

### 文章⑥ 独立工具的机会在「规划层」（content-planning-vs-booking）

- **标题**：AI 旅行规划正在变成预订漏斗——独立工具的机会在「规划层」
- **摘要**：2026 年赛道三条新闻：Tripnotes 停运、Mindtrip 上线 agentic 机票预订、Expedia 收购 Layla。资本把 AI 旅行卷向"可预订"，而预订层是重资产（库存/支付/售后）。独立工具的正解是把规划层做深：可修订（AI 出 diff、代码原子应用）、可验证（城市基准价估算 + TravelCritic 四维质检闭环）、可协作（share_token + 评论 + 投票）。
- **标签**：AI行程、产品策略、独立开发、LLM工程、AI Agent
- **平台**：掘金 / 知乎 / 公众号
- **发布时机**：与文章④《修订应该是一等公民》互为姊妹篇（一篇讲"修订是一等公民"，一篇讲"独立工具生存策略"），可在文章③后一起规划节奏
