# 巨头免费化之后：独立 AI 旅行规划工具还剩下什么

> 系列第 ⑭ 篇（收官）。前作 ⑬《第一次尝试就翻车：AI 旅行工具的信任缺口》
> 读者：在巨头阴影下做独立产品的工程师与独立开发者。

## 一、2026 年的行业地图

把今年发生的事排成时间线：

| 时间 | 事件 | 含义 |
|---|---|---|
| 2023-12 | Tripnotes 关停（被收购后） | 「好用的规划工具」也可以死 |
| 2026-05 | Mindtrip 对话内机票成交（Sabre + PayPal） | 规划层开始吞预订层 |
| 2026-06 | Troupe 倒闭 | 群组规划赛道洗牌 |
| 2026-07-31 | Expedia 收购 Layla | OTA 把独立工具收回体系内 |
| 2026-08 | Google Canvas 成为默认入口 | 搜索层直接给规划 |
| 2026-09-30 | Mindtrip Personal Travel Assistant（免费+主动监测） | 免费 + 深度记忆成为标配 |
| **2026-10** | **Tripnotes 2.0 回归在线**（tripnotes-2.webflow.io） | **关停 ≠ 需求消失** |
| 2026-10 | 中文巨头全面接入：千问×飞猪、元宝×同程、携程 TripGenie +400%、飞猪帮帮履约、千问 Go 打电话 | 入口之争白热化 |

Tripnotes 的「关停 → 重生」值得单独说：它证明了**note→map 这条需求是真的**，之前的失败更可能是商业结构（被收购后停摆），而不是需求不存在。这对独立开发者是个好消息，也是个警告——需求在，但活下来靠的不是需求。

## 二、两组互相矛盾的数字

- **AI 代理目前只占酒店预订 3-5%**（ZentrumHub 基于 150 万真实预订测算，2027 底预计 5-8%）；
- **但 65%+ 用户的规划第一选择已是内容平台与 AI 工具**，而不是携程。

翻译一下：**入口已经被 AI 拿走了，成交还没有。** 这正是规划层的机会窗口——用户在这里做决策，钱在别处花。

同时要看到成本结构：AI 规划 = 多轮 LLM 调用。免费 + 匿名 + 无限制 = 算力矿场。Mindtrip 能免费是因为它后面有预订佣金；独立工具没有这条腿。

## 三、独立规划层的四个生存条件

基于今年 18 份竞品分析和自己的工程实践，我把「活下来」拆成四个条件：

### 3.1 免费体验，但成本可控

- 确定性优先：预算、时间、自驾、体力、动态事实全部走规则库（零 LLM、可单测）；
- 降级链：重试→熔断→provider 兜底→数据源降级，避免单点故障放大成本；
- 不做匿名无限算力：免登录只给消费端（分享页 token），生成端需要登录。

### 3.2 独有深度：四根支柱

| 支柱 | 竞品状态 | 我们的实现 |
|---|---|---|
| **四维质检 + 可回溯** | 多数只有生成，没有独立审查 | TravelCriticAgent + T-A-O 轨迹 |
| **修订闭环** | 「重新生成」为主 | AI 出 diff、代码原子应用、失败回滚 |
| **行中陪伴** | 少数（MonkeyTravel 今日视图、Tripnotes 锁屏） | 今日视图 + 打卡/跳过/顺延 + 事件流通知 |
| **诚实预算** | 普遍模糊 | 城市基准价 + 口径标注 + 无 LLM 估值 |

这四件事巨头也能做，但它们**不做**——因为不直接带来成交，且会拖慢转化漏斗。这就是独立产品的缝隙：做那些「正确但不促进下单」的事。

### 3.3 输入自由：四通道 + 中文攻略

- 笔记 / 截图 OCR / 邮件 / 链接四通道导入（统一敌意剥离管线）；
- 中文攻略深度抽取（马蜂窝/穷游/携程 POI 链接 + 正文结构化），小红书明确降级为链接收藏——**不做打不过的仗**；
- 圆周旅迹用 85% 解析率证明了「攻略转行程」是刚需；我们做的是同一场景的低成本版。

### 3.4 社区内容库：从私人收藏到公共资产

- 灵感推荐（23 目的地规则库）解决「还没想好去哪」；
- 精选画廊 + 一键复制创建解决「想参考别人的路线」；
- 城市模板解决「明确目的地、直接改模板」。

这三件都是低成本留存抓手，且都不需要 API 凭证。

## 四、明确不做的事（同样重要）

- **不做预订闭环**：接分销商 API 是重资产，且会把「中立规划」变成「货架推荐」；
- **不做实时价格**：免费价格源不存在，付费源与免费自托管定位冲突（已出评估记录关单）；
- **不做 7×24 人工兜底**：用降级链 + 可回溯 trace + 确定性代码替代；
- **不做锁屏 Live Activities**：PWA 平台能力不支持，用今日视图 + 事件流通知覆盖核心需求。

**每一条「不做」都有评估记录**（`docs/nightly/evaluations/`），这本身也是差异化：诚实说明边界，比假装全能更容易获得技术用户信任。

## 五、给独立开发者的三条建议

1. **选一个「巨头不做」的深度**：质检、修订、诚实预算、行中陪伴——都是正确但不促成交的事，正是缝隙。
2. **把成本打下来**：规则库 > LLM，确定性 > 概率。每省一次 LLM 调用，就多一次免费用户能活的空间。
3. **把边界写出来**：哪些做了、哪些明确不做、为什么。技术用户会因此信任你，这是巨头拿不走的资产。

## 六、收官

这个系列从多 Agent 编排写到行业生存，其实在回答同一个问题：

> **当模型能力不再是壁垒，产品剩下的是工程纪律与产品判断。**

多 Agent 编排、强校验、容错、修订、质检、诚实标注——这些不是「AI 功能」，是**把一个不可靠的组件做成可靠产品**的方法。巨头有更多算力，但工程纪律和产品判断是公平的。

规划层不死，死的是没有深度的规划层。
