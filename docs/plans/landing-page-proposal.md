# 产品介绍页与未登录访问方案（Landing / Onboarding）

> 状态：方案设计（待选型落地）
> 日期：2026-09-28
> 背景：当前所有业务路由（`/`、`/plan`、`/trips/:id`）都被 `router.beforeEach` 登录守卫挡死，未登录用户只能看到登录页；产品能力（多 Agent 规划 / 对话式修订 / Plan B / 协同 / servicing）没有任何面向陌生访客的介绍入口。本文给出 3 个落地方案 + 竞品交互对标建议。

---

## 〇、现状与问题

**现状：**

| 路由 | 页面 | 是否需要登录 | 说明 |
|---|---|---|---|
| `/login` | AuthView | ❌ | 登录/注册（含右侧品牌视觉：slogan + 3 张功能卡） |
| `/share/:token` | ShareView | ❌ | 分享只读页（仅对持 token 者开放） |
| `/` | TripListView | ✅ | 未登录 → 弹回 `/login` |
| `/plan` | PlanWizard | ✅ | 未登录 → 弹回 `/login` |
| `/trips/:id` | TripDetailView | ✅ | 未登录 → 弹回 `/login` |

**问题清单：**

1. **没有产品介绍**：访客到达站点，无 hero、无功能说明、无使用引导，只有登录框。
2. **能力与访客之间隔着一道墙**：多 Agent 规划、对话式修订、Plan B、协作分享等差异化能力 100% 藏在登录后。
3. **登录页视觉是"注册陪衬"而非"产品介绍"**：AuthView 的右侧品牌区承担了部分品牌传达，但它服务的是登录转化，不是产品理解。
4. **无"先尝后买"**：无法免登录体验哪怕一次规划，转化漏斗缺失中间层。
5. **无 SEO / 分享落地**：没有产品页意味着无法被搜索、无法作为对外链接传播（与已有分享玩法割裂）。

**为什么不建议只改登录页？**
登录页解决的是"老用户回来 / 新用户注册"，不是"陌生访客理解产品"。二者使命不同；把产品介绍硬塞进登录页，会稀释登录转化。正确做法是给产品一个独立的"门面"，再让门面把访客平滑导向登录/注册。

---

## 一、三个方案总览

| 维度 | 方案 A：纯产品介绍页（Landing Page） | 方案 B：落地页 + 免登录试玩（Demo） | 方案 C：产品化 CMS 门面（Content Site） |
|---|---|---|---|
| 一句话 | 静态门面，讲清楚"我是谁、能做什么" | 门面 + 未登录把玩一次完整规划 | 把门面做成可持续运营的内容站点 |
| 未登录访问 | 只读介绍 | 可以尝试验证一次规划 | 介绍 + 精选行程 + 社区分享 |
| 后端改动 | 几乎为零 | 中（匿名草稿/试玩 token） | 中-大（内容模型 + 精选接口） |
| 前端改动 | 中（1 个新页面 + 路由守卫放行） | 大（试玩态 + 规划引导 + 结果收藏引导） | 大（多页面 + 内容管理） |
| 上线速度 | ★★★ 最快（可当日完成） | ★★ 较快（1-2 天） | ★ 慢（需持续运营） |
| 转化设计 | 弱（靠文案 → 注册） | 强（体验价值前置，注册后留存） | 强（内容种草 → 试玩 → 注册） |
| 维护成本 | 极低（静态） | 低（试玩是复用现有规划链路） | 高（需内容生产者） |

> 建议：**先 A（当日落地止血），随后升级到 B（把"能做什么"变成"体验一下"），C 作为有内容团队后的长期方向**。A→B 是同一页面渐进增强，不是推倒重来。

## 二、方案 A：纯产品介绍页（Landing Page）

### 目标
让陌生访客 30 秒内理解：**这是什么 → 能帮我做什么 → 我怎么开始**。

### 路由与信息架构

```
/           产品落地页（LandingPage.vue，public）     ← 新
/login      登录/注册（现有，右视觉区保留）
/plan       规划向导（登录后，现有）
...
```

- 根路由 `/` 从 `TripListView` 改为 `LandingPage`（**改守卫 meta: public**）
- 登录后的"我的行程"导航到 `/trips`（从 TripList 提取为独立路由），顶栏在登录态显示"我的行程"，未登录态显示"登录 / 注册"
- 访问 `/plan`、`/trips/:id` 未登录 → 仍弹回 `/login?redirect=...`（保留现有行为）

### 页面结构（移动端优先单列，桌面双栏/网格）

**1. Hero（首屏）**
- H1：`你的每一次出发，都从「随行」开始`（沿用品牌）
- 副标题：一句话讲清差异化 —— `多 Agent 协作规划 · 真实数据 · 可对话修订 · 可协作分享`
- 主 CTA：`免费开始规划 →`（登录/注册）；次 CTA：`看看它怎么工作 ↓`
- 视觉：产品真实截图（规划向导 / 行程详情），而非插画（**真实截图 > 示意图**，借鉴 Mindtrip 落地页教训）

**2. 产品能力四卡（How it works）**
用 4 张卡讲"能做什么"，每张配一句人话 + 能力标签：
- **AI 全程规划**：4 个专家 Agent 并行协作，查景点、看天气、找酒店、排行程
- **一句话改行程**：`西湖只留半天，晚上加知味观` → AI 出 diff，代码原子执行（可回滚）
- **旅行中也要用**：大交通方案、市内通勤、入住办理指引、优惠折扣（servicing 四卡）
- **一起计划**：只读分享链接、受邀编辑、评论、想去/不想去投票

**3. 差异化 / 信任区（Why us）**
- 真实数据（高德 POI / 天气；不造假）
- 质检透明（AI 规划全程 T-A-O 轨迹可视，四维质检评分）
- 规划层定位（免费开放、不绑架预订、可导出 PDF/图片/小红书笔记）
- 开源自托管（MIT）

**4. 演示区（可选，A 阶段可先用静态截图）**
规划向导三段演示：填写需求 → AI 专家协作（T-A-O 轨迹）→ 行程完成。A 阶段放 GIF/截图，B 阶段变成真试玩。

**5. 灵感 / 示例行程区（可选，A 阶段先静态）**
3-6 个示例行程卡片（杭州/成都/大理…）：目的地、天数、预算、亮点。点击 → 提示登录后查看/一键复刻（`/plan?dest=杭州` 预填）。

**6. CTA + 页脚**
- 最终 CTA：`现在就开始规划 →`
- 页脚：品牌 + 语言切换 + 开源链接（沿用 App.vue 页脚）

### 后端改动
- 几乎为零。示例行程可用静态数据或现有分享 token 指向的公开行程。
- 唯一建议：提供 1 个只读接口（`GET /api/v1/showcase/itineraries`）返回 3-6 个精选公开行程（若不想硬编码在前端）。

### 前端改动清单
1. 新建 `views/LandingPage.vue`
2. `router/index.js`：`/` → LandingPage（`meta.public: true`）；新增 `/trips` → TripListView；登录判定不变
3. `App.vue` 顶栏：未登录态显示导航（产品特性锚点）+「登录 / 注册」；登录态显示「我的行程」「AI 规划」
4. `api/index.js`（若走后端精选接口）+ i18n（zh-CN / en-US）
5. 复用现有 `btn-primary` / 品牌色 CSS 变量，视觉一致

### 验收标准
- [ ] 未登录访问 `/` 看到完整产品介绍，不弹登录
- [ ] 访问 `/plan`、`/trips/:id` 未登录仍弹回登录（行为不回归）
- [ ] 登录后 `/` 自动进入「我的行程」（或 `/trips`），顶栏正确切换
- [ ] 移动端 375px 无破版
- [ ] i18n 中英双语齐全
- [ ] `npm run build` 通过

## 三、方案 B：落地页 + 免登录试玩（Demo，推荐）

### 目标
在 A 的基础上，让陌生访客**不注册就能体验一次完整的 AI 规划**，把"听我说"变成"你试一下"。

### 核心机制：匿名试玩（Guest Demo）

1. **入口**：落地页 Hero 主 CTA 改为 `立即试玩（无需登录）→`，进入规划向导的"试玩模式"。
2. **试玩模式（PlanWizard 增加 guest 态）**：
   - 允许未登录用户填写目的地/日期/偏好，提交规划
   - **复用现有规划链路**（`POST /planner/plan`），但后端新增：
     - 匿名任务：`POST /planner/plan?guest=1` 或 `X-Guest-Token`，不绑定 user_id，任务结果以**临时 token** 关联（TTL，如 24h）
     - 试玩结果**不落库为 trip**（或落库为"匿名草稿"，用户注册后一键认领），避免垃圾数据
   - 前端试玩态：不显示"我的行程"等登录功能，结果页显示一条"注册后保存到我的行程"引导条 + 登录 CTA
3. **注册认领（Conversion）**：
   - 试玩完成后，CTA：`注册并保存这个行程 →`（注册成功自动将匿名草稿绑定到新账号，跳转 `/trips/:id`）
   - 变成产品最自然的转化时刻：**用户已经在"用"了，只差一个账号**
4. **限流保护**：匿名试玩按 IP / 设备指纹限次（防刷 LLM 成本），如每日 3 次；已登录不限。

### 成本与风控（这是 B 方案唯一真正的成本 —— LLM 调用）
| 风险 | 缓解 |
|---|---|
| 匿名刷规划消耗 LLM token | 限流（IP/指纹每日 N 次）+ 熔断器已存在（LLM breaker）|
| 试玩产生垃圾数据 | 试玩草稿不进入正式 trip 表（独立 guest 表 + TTL 清理），或标记来源 |
| 试玩结果无法找回 | 临时 token + 注册一键认领；提示"保存需登录" |

> 对开源自托管产品，匿名试玩的 LLM 成本由部署者承担——README 可注明"自托管可关闭试玩"（`ENABLE_GUEST_DEMO=false`），默认开还是关取决于部署策略。

### 前端改动清单（在 A 基础上增量）
1. `LandingPage` Hero 主 CTA → 试玩入口；加"如何工作"三段演示（真试玩内嵌 or 跳转）
2. `PlanWizard` 增加 guest 模式分支（表单 → 提交 → 匿名任务轮询 → 结果展示 + 注册引导条）
3. `stores/auth` 增加 `claimGuestTrip(token)` 认领逻辑
4. 后端：匿名任务接口 + 草稿表（或复用 PlanTask + guest token 字段）+ 认领接口 + 限流
5. 灵感区示例行程 → 点击进入试玩并预填（`/plan?demo=1&dest=杭州`）

### 验收标准
- [ ] 未登录可完整走通一次"表单 → 规划 → 结果"试玩
- [ ] 试玩结果页有明确"登录保存"引导，注册后行程可用
- [ ] 相同 IP/指纹超限后提示并引导登录
- [ ] 后端测试覆盖：匿名规划创建/认领/TTL/限流（沿用 FakeLLM）
- [ ] 已登录用户不进入 guest 分支，行为不回归

## 四、方案 C：产品化 CMS 门面（Content Site，长期）

### 目标
把落地页从"一次性的静态介绍"变成"可持续运营的增长引擎"：**内容种草 → 试玩 → 注册**。

### 结构（在 B 基础上增量）
1. **多页面**：`/`（介绍）、`/inspiration`（精选行程灵感库）、`/itineraries/:slug`（单行程公开详情）、`/blog`（可选）
2. **灵感库数据模型**：`ShowcaseTrip`（精选行程：标题/目的地/天数/预算/亮点/关联 trip_id 或静态数据）+ 标签 + 排序
3. **精选来源**：
   - 运营手工挑选（后台简单 CRUD）
   - 用户公开行程（`share_token` 已有公开访问能力，可加"申请上精选"）
4. **SEO**：每页 title/meta description/OG 标签；服务端渲染或静态生成（Vue 3 + Vite 可考虑 SSG 或预渲染）
5. **增长闭环**：灵感 → 试玩 → 注册认领 → 分享出去（再回到灵感库）

### 适合场景
- 有内容/运营人力，想把产品做成"目的地的内容入口"
- 需要 SEO 流量（中文搜索引擎对"XX 旅游攻略 AI"类关键词）
- 为将来商业化（订阅/赞助/内容合作）铺路

### 代价
- 内容模型 + 后台管理 + 前端多页面，工作量是 A 的 3-5 倍
- 需要持续内容供给，否则是空壳

## 五、竞品交互对标建议（Landing 交互细节）

> 来源：Mindtrip 落地页实抓结构、专业营销拆解（"How I'd grow Mindtrip"）、新华网/人民日报海外版 2025 年国内 OTA（携程/去哪儿/马蜂窝/飞猪）AI 功能报道、本仓库 09-22~09-25 竞品分析。

### 5.1 值得借鉴的交互（海外标杆 Mindtrip）

Mindtrip 落地页（实测结构）：
```
Hero: "Travel together. Mindtrip brings the world to you…" 
      [Start chatting] [Play video] [Learn more]
How it works: 5 步（Start chatting → Browse popular itineraries 
              → Get personalized recommendations → Plan with your crew 
              → Upload receipts）
Start Anywhere®: 粘贴链接/照片/PDF → 秒变行程（创意钩子）
Everything you need: 4 个能力卡（Photos maps+reviews / Tailored recommendations 
              / Customizable trip plans / Collaboration tools）
Get inspired: 热门目的地灵感区
CTA: Plan your trip (Flights/Stays/…) + Book a demo
```

**强交互点（建议吸收）：**
1. **Hero 主 CTA 直通产品（Start chatting → 直接进聊天）**——Mindtrip 把"开聊"当成第一动作，注册不是门槛。这正是我们"试玩"方案 B 的灵感来源。
2. **"How it works"用分步叙述而不是抽象卖点**——5 个真实使用场景，每个都是"用户怎么一步步用"。我们的四卡也应写成"用户步骤"：填写 → 规划 → 调整 → 分享。
3. **真实产品截图/视频 > 插画**——Mindtrip 被营销专家批评"hero 视觉没有传达产品"；我们落地页必须放真实 UI 截图（规划向导、行程详情、共享页）。
4. **"Start Anywhere"创意钩子**——把"从任意内容开始"（粘贴链接/照片）做成产品记忆点。我们对应的差异化钩子是：**"粘贴你的笔记/攻略，AI 帮你变成行程"**（笔记导入能力）。
5. **灵感区（Browse popular itineraries / Get inspired）**——展示别人做好的行程，既是内容又是转化入口。我们有分享/公开行程能力，天生可做"精选灵感"。

**Mindtrip 的坑（建议避免）：**
- 营销分析明确指出：**"访客不知道可以免费使用"+"藏在登录后"是它的转化率杀手**——落地页必须明示"免费"、必须给未登录用户可体验的东西（哪怕只是看完介绍）。
- 没有定价说明造成疑虑——我们可放一张"免费 / 开源 / 自托管"的清晰说明。

### 5.2 国内 OTA 的启示

| 竞品 | 交互亮点 | 我们可借鉴 |
|---|---|---|
| 携程 AI 行程助手 | 常驻 AI 浮动按钮（规划中随时提问）| 行程详情页可加"AI 助手"浮动入口（交互跟进，非本期） |
| 马蜂窝 AI 路书 | 主动提问（选择题引导需求）、行程备选方案 | 我们已有 questions + Plan B，落地页应把它们做成**可见卖点**（截图展示"AI 会问你几个问题"+"主案/备选切换"） |
| 飞猪问一问 | 多智能体 8 角色、手绘攻略分享 | 我们的多 Agent 是技术差异化，落地页用"五位专家协作"可视化（已有 T-A-O 轨迹） |
| 去哪儿 | 小红书笔记导入 → 行程 | 我们的笔记导入是相似的"想法搬运工"，落地页应重点讲 |

### 5.3 落地页转化路径设计（对比总结）

```
当前（缺失）:  访客 → 登录页 → [流失]
方案 A:       访客 → 产品介绍 → 注册 → 使用
方案 B:       访客 → 产品介绍 → 免费试玩一次 → 注册认领 → 使用   ← 最优转化
方案 C:       访客 → 内容/灵感 → 试玩 → 注册认领 → 使用 → 分享 → 回到灵感库
```

**关键交互决策（建议）：**
1. 主 CTA 永远指向"开始/试玩"，而不是"登录"（登录是手段不是目的）
2. 首屏必须出现**真实产品截图**，30 秒内让访客"看懂"产品
3. **明示免费**（`免费 · 无需信用卡 · 可自托管`）
4. 演示/试玩尽量**无需登录**（哪怕只有 1 次）
5. CTA 之后不给空落落的结果——试玩完成后立刻给"保存/分享/继续"的下一个动作
6. 落地页与产品共享同一套设计 token（品牌色/圆角/卡片），观感统一

## 七、需要用户决策的点

1. **方案选型**：A / B / C / A→B 渐进（推荐）
2. **根路由归属**：`/` 给 Landing，登录后首页跳 `/trips`；还是保留 `/` 给登录用户、Landing 放 `/about`？（推荐前者——落地页即门面，SEO 也需要根路径）
