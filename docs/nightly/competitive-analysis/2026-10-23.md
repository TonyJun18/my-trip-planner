## 1. 竞品清单（★=本夜新增标的）

- **TripTrackAI**（triptrackai.com，★本夜重点）：2026 增长最快的「行中/预订后」工具——**Gmail 自动导入 + 实时航班追踪（门变更/延误/行李转盘）+ 收据 OCR + AI Concierge + 推送通知**，App Store 4.9、18K+ 活跃、58K trips。Free 档：3 个行程/月 10 张收据/每日 3 次 AI 问答；Pro $11.99/月（或 $99.99/年）：无限行程、实时航班、Gmail 自动导入、OCR、CSV/PDF 导出。输入侧走「凭证级自动化」（Gmail OAuth）路线，与我们的零凭证粘贴版刻意区隔。
- **Feedtrip**（feedtrip.app，★本夜新增）：**社交收藏新赛道**——TikTok/Instagram 分享 sheet 把「已保存的视频」变成地图上的地点→再变成行程；「视频被删也不丢」（保存时即落库）；支持 Google Maps 导入。Plotline、RoamRecs、Dream Trip 同场竞争。Unite.AI 2026-10 榜单收录。这是「输入自由」的最新形态：收藏即起点。
- **PlanYourTrip**（planyourtrip.travel，★本夜新增）：无实时价的诚实定位（「AI 不预订、不给实时价，是灵感生成器+快起点」）+ **密码保护 collaborator 链接——知道密码即成 co-owner 可编辑**，实时同步；免费+每日消息限额。与我们的 share token 免登录消费形成对照：他们做「链接+密码=共同所有权」，我们做「token 分权（edit/vote）但无密码」。
- **Travel Binder**（App Store，★本夜新增）：**完全离线、无账号、数据在设备上**的极端「数据主权」派——路线优先（先城市+晚数，其余自动展开）、PDF 导出免费、Markdown/日历 Premium、免费 1 个行程。与 Wanderlog 的「数据锁死」互为反面教材。
- **Travel76 / 7x6 AI**（7x6.ai，★本夜新增）：苏黎世团队，**多 agent 并行编排（LangGraph：航班/酒店/租车/活动四 agent 同时检索）+ WebSocket 流式 + 协作工作区**；早期访问阶段。技术栈与我们（FastAPI+LangGraph+WS）同构，但主打「5 小时规划→5 分钟」的预订前置聚合，无质检/无诚实预算叙事。
- **Wanderlog**（对照，数据锁死实证）：7wanders 2026-10 实测——**免费仅 print view（浏览器存 PDF）**；Pro 只有 Google Maps places 导出；**无 CSV/KML/JSON/ICS 全量导出、无日历导出**；expenses-to-CSV 仅限预算部分。用户数据被锁在 app 内，迁移只能靠打印。
- **Stippl**（对照）：2026 评测第一（stippl.io 自测 + 第三方），**免费档标配「打包清单+预算+费用分摊」三件套**+协作编辑；我们没有的分摊是其差异化核心之一。
- **MonkeyTravel**（对照）：行中三件套仍是最全（今日视图/顺延/跳过 + 打包清单 + 费用分摊 + 变更 feed），4 级投票+参与率+角色权限已与我们拉近（我们 participation 已落地，四档投票未做）。

## 3. 差距 → 行动项（我们可补的差距 / 可借鉴的亮点）

1. **【补功能】行程导出与离线评估——“输出自由”真空洞**（Wanderlog 数据锁死实证：免费仅 print view、无 CSV/KML/JSON/ICS 全量导出，7wanders 2026-10 逐项核验；Travel Binder 免费 PDF 导出、Stippl CSV 导出为反证——**2026 年整个 AI 规划市场把用户数据锁死在 app 内，导出/离线是普遍真空**）。我们「输入自由」已有四通道（笔记/截图/邮件/链接），但**输出侧零导出代码**（search_files 全仓无 export/offline/pdf/csv 服务），不对称。最小版（零凭证）：后端 JSON 导出端点（复用 share 只读序列化，含 stops/预算/质检 warnings，测试覆盖）+ 前端「导出/打印」入口（打印样式视图，浏览器存 PDF）；PWA 离线壳（sw.js 已有预缓存）单独评估缓存 API 的可行性。这填补「数据主权」差异化，且与「规划层小而锋利=用户数据属于用户」的叙事（14 文）同构。
   → 行动项 slug：**task-export-offline**
2. **【补功能】行中费用分摊最小版**（Stippl 免费档标配「打包清单+预算+分摊」三件套、MonkeyTravel 费用拆分 vs Wanderlog 无预算无分摊——「行中管理一体化」仍是 2026 分水岭；10-19 备注已确认我们缺口）。仓库核验：预算视图已有人均口径（travelers>1），**但无行中费用记录与分摊**。最小版（零凭证）：费用记录（金额/类别/支付人 traveler 名）→ 按人均汇总结余 → 复用预算视图透出。与 task-packing-expense 同批「行中三件套」收尾。
   → 行动项 slug：**task-expense-split-mini**
3. **【评估候选】社交收藏→地点**（Feedtrip 2026 新赛道：TikTok/IG 分享 sheet→地图→行程，视频删除仍保留；Plotline/RoamRecs 同场；这是「输入自由」的最新形态=收藏即起点）。我们 link_import 只 og:title/description，小红书/IG/TikTok 分享页反爬大概率挡（与 task-link-import-zh-eval 同构结论）。评估「**粘贴分享文本（caption+链接）**」→ 规则提取地点候选的可行性（与 email-import 零凭证粘贴版同构，不抓 URL 不碰反爬）；可行则最小版 + 测试，否则记降级关单（现有链接收藏已兜底）。
   → 行动项 slug：**task-social-collection-eval**
4. **【评估候选】分享链接访问控制**（PlanYourTrip 密码保护 collaborator 链接→知道密码即成 co-owner、MonkeyTravel no-account 邀请 vs 我们公开 share/edit token 无密码无撤销）。评估密码保护/到期/一键撤销的成本边界（schema 演进 + share 生命周期校验 + 前端收密码交互）；可行则最小版密码保护，否则记录降级。这是防御性差距，优先级低于 1/2。
   → 行动项 slug：**task-share-gate-eval**
