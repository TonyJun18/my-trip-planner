## 0. 一句话结论

新入局者不再拼「生成行程」，而是拼**规划后链路**：Stardrift 把「多城市 + 导入 + 盯价」做成一条龙，Butter Agent 把「群组 + 账单分摊」做成独立产品，Fortrip 把「验证 / 优化已有行程」做成独立品类。**「生成之后怎么办」正在成为 2026 分水岭**——与前几夜（agentic 预订收购潮、43% 缺陷研究、诚实边界）完全同向。

## 1. 竞品清单

### 1.1 Stardrift（stardrift.ai）——多城市 / 导入 / 盯价一条龙
- AI 旅行规划对话式工具：单次对话里完成航班/酒店/活动检索，输出可编辑、可分享的行程，带交互地图；编辑器支持拖拽天/站、导入既有预订邮件。
- **2026-09-15 changelog**：①图片上传（预订确认单/行程截图 OCR 进行程）；②邮件转发（个人转发地址，不连 Gmail 的用户可用）；③付费订阅机票价格盯梢（实时价格变化告警）；④酒店搜索支持精确房型并可直接预订。
- **Reels 导入**：「从 TikTok/Instagram Reels 直接导入地点并建行程」是新卖点（与 11-13 Reels 红海潮同轨）。
- 免费对无卡用户开放（best-ai-travel-planners 摘要），付费 Pro 解锁盯价等。

### 1.2 Butter Agent（App Store, iPad）——群组旅行 + 账单分摊
- 「Bring the plan you already have or let Butter build one」：粘贴已有计划（Notes/chat/doc）→ 保留天/时间/地点 → 钉到真实地点 → 用户 review 后才添加任何东西；无计划则粘贴整段让 Butter 找目的地与日期建行程。
- AI 规划：规划前先展示「它理解了啥 + 会用多少 credits」；研究真实地点、钉在地图上、保留引用网页；细化用自然语言，回退免费；支持**开放时段占位**（如「2–4pm around Shibuya, something relaxed」）。
- 群组 + 账单分摊：一起旅行 → 一张地图看全程 → 沿途提问 → **分摊每笔费用并一键结清**（v2.0 全新 UI）。
- 付费模式：credits 制（AI 规划消耗 credits，规划前明示用量）。

### 1.3 Fortrip（fortrip.ai）——规划后验证 / 优化品类
- 定位「AI travel optimizer」：不是再生成一个行程，而是**检查/优化已有的行程**——路线顺序、酒店日期、总成本。
- 多城市行程：城市顺序/天数/交通组合/酒店排布一起规划（「cities, transit legs and pacing planned as one route, not three separate trips stapled together」）；有专属 Transport Optimizer。
- 「It asks before it assumes」：影响行程的决策点暂停询问并给推荐。
- 免费档可用，Pro 提额度；主打规划全流程（inspiration → validation → optimization → refinement）。

### 1.4 巨头侧（对照锚点）
- **Mindtrip**：11M+ POI 数据库；2026 在 chat 内完成机票/酒店预订；09-30 Personal Travel Assistant（记住偏好、盯价、briefings/packing lists）；EU 托管部署 + 价格下降告警；免费档（无明确数值上限）。
- **Gemini / Google Canvas**：AI Mode 内 Canvas 行程规划（US Labs 扩大）；原生接 Google Maps/Flights/Hotels/Gmail 确认单；无统一 planner 视图（复制到 Docs），Gemini App 11-17 起 Gems 转只读、12-17 移除（「skills」替换）。
- **Wanderlog**：免费档 AI 5 条/行程封顶、Pro $39.99/年无限 AI；行程数与协作数不限制（11-08 已记录）。
- **Wonderplan**：免费（FAQ「at least for now」）；干净日卡 + 预算 + PDF 导出；预算导向。
- **Layla / Tripadvisor**：都被巨头收编或免费化（Expedia 收购后转真人顾问成交；Tripadvisor AI 免费日卡可编辑可分享）。

## 3. 差距 → 行动项（补功能 / 内容沉淀 / 候选评估）

> 按「与我们的定位（小而锋利规划层、零凭证、可修订、质检 trace）匹配度」排序；全部先入 §2 候选池，由用户/队列腾位后晋升 §1（手册 §5 维持规则）。

1. **【候选评估·backend】task-open-slot-eval：开放时段占位（open slot）** — 证据：Butter Agent「开放时段如 2–4pm around Shibuya」是 2026 新入局者明确差异化（规划层对「未定型时间」的表达）；我们 grep backend 无 open_slot/自由时段语义，`pace=relaxed`（profile）只是节奏倾向、`plan_b.Relaxed` 是过满日变体，均**不是**「用户显式声明留白时段」的结构化占位。评估：PlanRequest/stops 增加「开放时段占位」（时间段 + 自由度 + 偏好类别，无固定 POI）→ 排程/质检/修订链路如何表示（不打破 DrivingGate/TimeGate 确定性约束）；可行则最小版（占位透出 + 排程不硬塞站点 + 质检豁免逻辑）+ 测试。规模 M（拆 2 夜）。若评估不过：记录降级关单（与 task-guest-trial 同构）。

2. **【候选评估·backend】task-multicity-optimizer-eval：多城市交通优化器入口** — 证据：Fortrip 主打「city order + transit legs + pacing as one route」+ 专属 Transport Optimizer；Stardrift 也是多城一条龙；我们 task-multi-city-segments 已实现多段排程 + 段间交通占位站（规则估算），但**没有**「调整城市顺序/交通组合」的优化动作（solver/day_optimizer 是日内站点级）。评估：城市级重排（复用 day_optimizer 贪心 + DrivingGate 语义）+ 段间衔接质检（到港 vs 首站开放，linking time_validation）；可行则最小版（城市级优化端点 + 测试），不可行记录降级。

3. **【候选评估·frontend+backend】task-price-watch-mini-eval：轻量价格盯梢（降级版）** — 证据：Stardrift Pro 盯价 / Mindtrip Personal Assistant 盯价=「主动值提醒」两个新实证；task-price-alert-eval（10-10）已评估免费价格提醒 API 不存在并降级为行程内事件通知。本轮不推翻结论，但**补一个零凭证中间档**：对用户已输入的预订（booking 表已含金额/日期）+ 规则汇率，做「行程内价格台账 + 波动提示」（不接外部实时价，只对用户自己录入的金额做基线/变更提醒，复用 trip_events）。评估是否有价值 → 可行最小版（台账 + 变更事件 + 测试），否则维持既有降级。

4. **【候选评估·frontend】task-paste-any-plan-eval：粘贴任意已有计划 → 结构化行程（Butter 式）** — 证据：Butter 主打「paste a plan from Notes/chat/doc → 保留天/时间/地点 → 钉到真实地点 → review 后才添加」；我们四通道导入（note/email/social/screenshot/link）是「单通道结构化提取」，缺「整段已有行程计划 → 一站一站点位保留」的粘贴解析。评估：复用 note_import 敌意剥离 + 行程骨架识别（天/时间/地点行 → 候选站点 → 勾选并入）；可行则最小版（「粘贴已有行程」Tab 预填 PlanWizard）+ 测试；与 email-import「零凭证粘贴版」同构。

5. **【内容沉淀】content-planning-after-generation：文章「生成之后：AI 行程规划 2026 的分水岭移到规划后链路」** — 证据：本轮三家新入局者全部主打规划后能力（Butter 群组+分摊、Stardrift 多城+导入+盯价、Fortrip 验证+优化），与前几夜（agentic 预订收购、43% 缺陷研究、诚实边界、Tripnotes 2.0 回归）构成完整叙事；写 16 文（接 15 文《收购季》）：规划层生存位=「生成只是起点，验证/修订/行中/协作才是护城河」，落到 T-A-O/四维质检/行中三件套/协作/预订台账/导出双路径。代码引用逐条核验与仓库一致。

6. **【备注·不排期】Butter 式「明示 credits 成本」** — 我们无 credits 经济，quota 软提示已够；不做付费经济。**Stardrift 图片上传（确认单 OCR）** 与既有截图导入重叠，是否扩展「确认单图片→结构化条目」并入 3 中评估，不单独立项。**一键结清资金动作** 违反零资金边界，不做（任务已决裁）。
