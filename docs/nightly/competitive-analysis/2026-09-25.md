## 一、竞品清单（本夜聚焦 6 款，2 海外 + 4 国内）

1. **TripPlanner AI / TripPlannerAI**（nxvoytrips.ai，海外）—— 2026 主打**自驾 AI 路书**：扫描真实自驾游记 + 实时路况 + 车辆类型（油/电）精确计算燃油/充电经停、风景路线（非最快高速）、隐藏宝石、本地美食，导出 Google Maps/PDF/分享链接，免费。短板：区域聚焦（印度线路为主）、无预订、无协作、模板化修订。
2. **携程 AI 行程助手**（ctrip.com/tripplanner/，2026 正式铺开）—— 一站式「规划到预订」：20M+ POI、实时交通/门票/酒店整合、**画布式编辑**（重命名/重排/替换/删除/备注）、**常驻 AI 浮动按钮**实时建议、地图路线预览、三问起步、可导入 Trip.com 历史订单、**人工定制师团队兜底**。短板：需登录、绑定携程生态、无质检透明、无跨会话记忆（弱）。
3. **去哪儿 AI 旅行工具箱**（2025-09 上线）—— 「一个核心助手 + N 个细分场景助手」（行程规划助手 / 机票 AI 小驼 / 酒店售后 AI 客服），**小红书笔记导入生成个性化方案**（种草 → 行程转化），与小红书内容生态合作。短板：AI 回复偏简略、需登录、无协作/导出能力弱。
4. **马蜂窝 AI 路书 / AI 小蚂**（2025-2026 持续迭代）—— 主动提问（选择题引导需求）、**行程备选方案（Plan B）** 与**避峰策略**（国庆期用户关注度最高的两个功能）、对接「当地指路人」真人专家一对一、博主实测数据反哺（踩雷按钮）、摄影机位/最佳时间等深挖细节、15 年真实旅行数据（游记语料）。短板：整体偏向目的地内容生态，规划产物导出/协作弱，无开放 API。
5. **飞猪 AI 问一问**（2025，多智能体驱动）—— 8 个细分角色（行程助手/路线定制师/交通顾问/酒店顾问/攻略达人/本地导游/预算管理师/服务保障专员）——**与我们多 Agent 单职责编排同构**；多模态输入（文字/语音/方言）、**手绘攻略分享图**、实时位置本地生活服务、图片+商品卡片+链接的富文本行程。短板：绑定飞猪交易生态、无质检 trace、规划产物不可导出为结构化数据。
6. **Wonderplan**（海外，承接上夜）—— 纯免费、表单输入、PDF 导出、增删重排，无协作无预订。职能最简单、门槛最低。本夜不再展开。

## 三、我们可补的差距 / 可借鉴的亮点（本夜 5 条）

### 差距 → 行动项

1. **【补功能】笔记/种草文本导入——规划层的「想法搬运工」（Tripnotes 范式复活 + 去哪儿小红书导入验证）**
   现状：用户只能在表单里填需求，无法把已有的攻略笔记/种草内容直接喂给系统。去哪儿「小红书笔记导入生成个性化方案」证明这是国内刚需；而海外 Tripnotes.ai 当年正是靠「粘贴你的旅行笔记 → 整理成行程」起家（2023 年 45 天百万用户），被收购停运后**这个交互范式没人继承**——正好是我们「规划层」定位的天然入口：不绑架预订，只帮用户把想法变成可执行行程。
   → 行动项：`task-note-import`：行程创建页支持「粘贴笔记/攻略文本」→ 后端结构化提取候选站点（名称/建议停留/备注）→ 前端展示候选可勾选进入行程（与 AI 生成结果合并）。验收：粘贴文本可生成站点候选 + 测试覆盖（恶意注入文本按敌意输入处理：只提取、不执行、不污染 system prompt）。

2. **【补功能】Plan B 备选方案（马蜂窝 AI 路书确认是用户高频需求）**
   现状：todo 中早有备注「行程备选方案（Plan B）待 task-roadtrip-mode 完成后评估」——roadtrip-mode 已于 09-23 落地，评估条件已满足。马蜂窝数据显示「备选方案」与「避峰策略」是用户使用 AI 规划时最关注的两个方向（主动提问已覆盖避峰）。
   → 行动项：`task-plan-b`：规划时同时生成 1 个备选行程骨架（节奏/取舍/预算档不同），详情页可一键切换对比（主案+备案并排 diff 视图，可直接把备案提升为主案）。验收：规划响应含 plan_b 字段 + 前端切换对比 + 测试覆盖。

3. **【补功能】自驾场景增强：长途经停/充电建议（TripPlannerAI 差异化功能）**
   现状：DrivingGate 已做站点间距离约束与折返告警，但没有「如何在超距行程中插入经停」的主动建议。
   → 行动项：`task-driving-stopover`：超距站点对（> 单日驾驶阈值）时，质检/规划上下文给出「建议中间经停点」提示（基于距离中点附近 POI），前端在自驾校验告警中展示。验收：超距行程产出含经停建议 + 测试覆盖。低-中优先级，可与 task-plan-b 合并评估。

4. **【内容沉淀】《国内 OTA 也在做 AI 行程了——独立规划层为什么还能活》**
   本夜新格局信号：携程（一站式规划到预订 + 人工定制师）、去哪儿（AI 工具箱 + 小红书导入）、马蜂窝（AI 路书 + 指路人）、飞猪（8 角色多智能体 + 手绘攻略）——**国内预订闭环同样在形成**。海外版「规划层生存策略」文章（07）已发布就绪，国内视角是姊妹篇：用户被 OTA 绑定在「规划即预订」的漏斗里，独立工具的机会在「规划本身的服务质量」——可修订（diff）、可验证（质检 trace）、可协作、可导出、不受平台库存绑架。
   → 行动项：`content-domestic-planning-layer`：写一篇发布就绪文章（docs/articles/08-…），以携程/去哪儿/马蜂窝/飞猪 2025-2026 功能为引，讲「规划层 vs 预订层」在国内语境下的边界与生存策略，承接 07 文做姊妹篇，发布清单补卡片。

5. **【内容沉淀】人工兜底的透明化表达（携程定制师 / 马蜂窝指路人的反向思考）**
   OTA 有真人兜底（定制师/指路人），开源自托管工具没有——这是客观短板，但也是差异点：**我们的「兜底」是工程化的降级链与质检 trace**（LLM 失败 → 结构化降级 → schema 兜底，坏答案可回溯），而不是黑盒卖给用户。把这套「质量兜底哲学」写进 README/文章，是规划层透明定位的一部分。
   → 行动项（轻量）：`content-quality-fallback`：README 增加「质量与兜底」小节（降级链 + 质检 trace + 已知局限表格同步），一并完成 09-24 遗留的 content-readme 收尾。
