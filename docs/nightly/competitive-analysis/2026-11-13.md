## 1. 竞品清单（★=本夜新增/重点）

### 1.1 ★「Reels 导入」红海潮（App Store 2026-11 一周 8+ 新 app 全押同一入口）

> 共同范式：**分享/保存 Reels → AI 识别视频中每个地点 → 钉到地图 → 按天数生成行程**。与 11-10 Plotline collect-first 同源，但已从「一个差异化新入场者」膨胀为「默认入口」。

- **Rhyme**（★App Store，iPhone Duo 适配 + iOS 27）：1-tap save——一键拉取视频中提到每个地点上地图；master collection（餐厅/地标/咖啡/隐藏 gem + 原帖链接 + 评论）；告诉天数按日连线不 zig-zag；**复制社区指南/朋友行程 + 分享链接**（community clone 与我们的画廊 clone 同构）；Google Maps lists/notes/photos 一起收。→ 交互亮点是「saved folder 本来就该被用」的收藏先行动机。
- **Travo**（★，10,000+ 下载）：**粘贴 TikTok/IG/YouTube 链接识别视频地点**入行程（三平台）+ 全 AI 行程/weekend getaway。→ 链接粘贴形态与我们 link_import 同入口，但它是「视频内容解析」，我们是 og 元数据。
- **Scoop**（★）：**转发预订确认邮件自动建行程**（flight/hotel/reservation 单时间线）+ 视频导入 + 交互地图 + 公开 trip 链接。→ 与我们的 email-import 撞车，它是新 app 的标配功能而不是差异化。
- **Triparchi 4.0**（★）：share reel → 地点上地图；**book stays near your plan**（行程附近酒店）+ **split costs with friends** + **country guide for every trip**；免费档 10 imports + 5 Archie messages，Pro 解锁 unlimited import + Swipe to discover + 酒店 15% off。→ 「预订 + 分摊 + 国家指南」三件套闭环化，免费档用「导入次数 + AI 消息数」计量（与巨头 tokenomics 治理同构）。
- **Dream Trip**（★）：share → pin 3D 地图（分组 by city/country）；reel tips 随地点保留；lists（Tokyo eats…）；AI 按 vibe/pace 路由 saved places，**真实营业时间 + 步行路线 + 用餐时段餐厅**；**行后照片自动附加到正确地点**；导出 calendar/单日 Google Maps；18 种语言。→ 亮点：营业时间/步行/餐饮时段 = 我们的 TimeGate/餐饮锚定同向；「照片自动归位」= 行后记忆（见 1.3）。
- **MapDreamy**（★）：reel 导入 + **Explored（走过的街道路线点亮 + 国家计数，私密默认）** + **AI assistant 聊天改行程**（「Add a ramen spot near the hotel」「Something for Tuesday morning」）+ 真实航班/酒店确认号围绕建行程 + collections 整理 + 应用内发现 feed。→ 「街道路线点亮」是行中/行后可视化新亮点（护照徽章的街道级变体）。
- **Pictoura**（★）：reel 导入 + 18 city guides 170 已核验地点 + 拍照位/pose 建议；**Premium 订阅制（weekly/monthly/yearly）**，免费档基本不能规划（trip planning 需订阅）。→ 内容库先行的订阅模式；「已核验地点」= 质检营销话术。

### 1.2 ★MonkeyEatingMango 356 行程缺陷研究（2026-09-08，11 月被 Reddit/横评广泛引用）

- 方法：**356 个真实客户 AI 行程、2,735 个规划日、268 目的地、284 城市、61 国**；缺陷判定全部**对照外部数据源**（live venue listing 营业时间/永久关闭 + 路线距离计算），不读模型自述文本。
- 结果：**43% 的规划日带至少一个可验证缺陷**；六类可复现失败模式；**周一承载 53% 的闭馆类缺陷**（周一闭馆是最大单一模式）；重复站点与时间错误强关联（有重复的行程中 93% 同时有时间错误、81% 有超闭馆时间访问）。
- 修复：**1,054 处缺陷在交付前被检出并修正，修复率 79.6%**；「修复无法修复的才用红色标在活动上」（诚实标注）。
- 用户侧含义：三位检查（营业时间/路线距离/…）能抓住旅客最可能遇到的大部分问题；「maps listing 几秒就能回答它」——**质检是工程（外部校验），不是 prompt 运气**。
- 我们的对照：TimeGate（open-hours 规则库 + explicit 优先）+ dynamic_facts（周一闭馆/免费周日特例表）+ weather_gate + 四维质检/T-A-O trace + DriveGate 路线约束，正是「模型外校验」工程化路线；「周一闭馆」与 dynamic_facts._weekly_closed 完全同构（核验在案：dynamic_facts.py 2 处 weekly_closed、time_validation.py time_gate 在案）。

### 1.3 ★Meridian Dispatch（iPhone only，Alice Capital LLC）—— BYO-AI + 行后记忆

- **connector**：在 Claude/ChatGPT/Grok 里加 connector 登录一次，你的 AI 就能在 app 内建行程、边聊边改、读你的行程；**也可以 1-tap 导入任意 AI 聊天产出的行程**（import guide 粘贴 prompt → 链接回流）。
- **行程变日记**：照片 + 每日本文 → magazine 布局 prose journal + print-ready PDF + 短视频；**app 从不请求定位、照片绝不上传**（本地处理）。
- 范式：**规划在 app 外（用你已有的 AI），行程 + 记忆在 app 内**。我们是「AI 在 app 内（chat-trip-data-flow + 详情页问 AI）」+ story 故事卡（三渠道模板 + PII 过滤）为近似对应物；「照片→日记」与 photo-import-eval 的 EXIF 素材同源，但要系统媒体权限（原生壳前置）。

## 3. 差距 → 行动项

1. **【新增·候选评估】task-share-target-eval：PWA Web Share Target 接收分享（backend+frontend）**——「Reels 导入潮」8+ app 全押原生 share sheet（Rhyme/Dream Trip/MapDreamy…），Stardrift 把视频导入当新卖点；我们五通道导入是「主动粘贴文本」形态，缺「**被动接收分享**」入口：用户在 TikTok/IG 点分享时把链接/文本直接发给 PWA（`manifest share_target` + Service Worker 路由），预填 social_import（粘贴文本版）或 link_import（链接收藏兜底），零凭证零抓视频。11-10 task-social-favorites-flow-eval 曾把 Web Share Target 登记为「不排期」，本夜竞品潮把它推到候选评估前排。评估点：iOS/Android 浏览器 share_target 支持面（iOS Safari 支持状态）、与「粘贴文本」入口的叠加体验、无分享上下文时的降级。（验收：评估记录（平台支持矩阵 + 与既有导入通道的关系）+（若可行）manifest share_target + SW 接收路由 + 预填社交导入 + 测试覆盖；不可行记降级关单）→ **slug：task-share-target-eval**
2. **【新增·小补功能/候选评估】task-monday-closure-coverage：周一闭馆特例覆盖度审计 + 补类目（backend）**——MonkeyEatingMango 量化实证「**周一承载 53% 的闭馆类缺陷**」（356 行程/2735 天/61 国），而我们 dynamic_facts._weekly_closed 已有周一闭馆基准但覆盖类目未系统审计（博物馆/美术馆/纪念馆/动物园/政府场馆等）。最小版：审计 _weekly_closed 类目表 → 补高频周一闭馆类目 + 排程校验 warning 联动 + 测试覆盖；「交付前修复率 79.6%」也提示我们把「检出-建议」闭环做得更显性（前端 timegate-card 已透出）。（验收：审计记录 + 补类目 + 测试覆盖（命中/未命中/显式特例豁免三路径））→ **slug：task-monday-closure-coverage**
3. **【新增·内容沉淀】content-ai-fault-study-43：43% 缺陷研究补 12/13 文（内容沉淀，docs）**——MonkeyEatingMango 356 行程量化研究是「质检底线」系列最强实证（43% 规划日带缺陷 / 2735 天 / 61 国 / 六类失败模式 / 周一 53% 闭馆错 / 修复率 79.6% / 检查在模型外对照外部源）；补 12 文《AI 旅行翻车实录》或 13 文《信任缺口》（11 月二更已含诚实边界，本文案更偏工程可修性）——「质检是可度量、可修复、可标注的工程，不是模型运气」。（验收：docs/articles/12-* 或 13-* 补「2026-11 三更/增补」段（日期明确 + 六类模式表 + 修复率 + 与 TimeGate/dynamic_facts 对应）+ 发布清单注释；代码引用逐条核验与仓库一致）→ **slug：content-ai-fault-study-43**
