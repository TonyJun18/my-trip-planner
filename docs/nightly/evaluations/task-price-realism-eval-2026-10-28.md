# task-price-realism-eval 评估记录（2026-10-28）

> 背景：预算可信度是行程工具核心信任点。当前 estimated_cost 以类目参考价 + 酒店城市基准价
> ×档位×评分修正估算（零凭证兜底），真实价格可能差出一倍。本任务评估真实价格数据源；
> 结论：**高德 POI `extensions=all` 的 `cost`（人均消费）为可用零新增凭证源，已实现最小接入**。

## 二、结论：最小接入已实现（backend）

**方向**：高德 POI 搜索是规划链主数据源（`search_pois_amap`），此前用 `extensions=base` 且
注释声称「景点门票等实际价格高德不返回」——已过时。官方文档确认 `extensions=all` 时返回
`cost`（人均消费，仅存在于餐饮/酒店/景点/影院类 POI）。

**字段位置注意**：v3 place/text 接口的 `cost`/`rating` 实际位于 `biz_ext` 深度信息下；
POI 2.0 接口为 POI 顶层字段。为兼容两种返回结构，实现采用**顶层优先 + biz_ext 兜底**双读。

**改动**（`backend/app/agent/tools.py`）：
1. `extensions=base` → `all`：POI 搜索结果附带深度信息（cost/rating/tag）；
2. 新增 `_parse_amap_cost`：解析 cost（字符串/数字），缺失/非法/≤0 → 0（不编造）；
3. 新增 `_parse_amap_rating`：解析 rating（0-5），非法 → None，越界裁剪；
4. 景点/美食 `estimated_cost` 取高德人均消费（真实价格进预算视图）；
5. 酒店维持「城市基准价 × 档位倍率」估算（高德 cost 对酒店是人均消费而非房价，口径不变）；
6. POI 统一结构新增 `rating` 字段透传（前端候选卡可展示）；
7. cost/rating 均顶层优先、`biz_ext` 兜底（双读，防字段位置漂移）。

**验收**：`tests/test_price_realism.py` 11 例（解析 3 + rating 边界 1 + 景点/美食/酒店/缺失 4 +
extensions 参数 1 + 顶层优先 1 + biz_ext 兜底 1），全套 **501 测试通过 + 1 skipped**。
前端无需改动（预算视图已有「估算口径」标注，真实人均消费自动流入）。

## 三、合规与诚实边界

- **数据性质**：`cost` 是高德聚合展示的「人均消费」参考口径，非交易/实时价格，
  仍属估算层级；前端「参考价，以实际询价为准」标注继续有效（**不宣称实时价**）。
- **不编造原则**：cost 缺失/非法一律 0，绝不拿别的类目价格顶替；酒店房价明确无源，不硬凑。
- **数据源熔断**：高德不可用时自动降级 Tavily 路径（¥ 正则启发式 + 酒店基准价），链路不变。
- **升级空间**：携程/Booking 类分销 API 与「免费自托管规划层」定位冲突（与 price-alert-eval、
  booking-closure-eval 同构），维持不做；如需运营侧校准，可后续加「城市×类目人工特例表」。

## 四、遗留

- `rating` 已透传到 POI 结构，但前端候选卡展示接线视窗口另立；
- 多币种汇率不在本任务范围（沿用 budget_service 注释口径）。
