# task-import-recall-benchmark 评估记录 · 2026-11-10

> 来源：2026-11-10 竞品分析 §导入可靠性比拼（Plotline vs Wanderlog）
> 结论：**评估通过，落地「导入召回率评测基准」（固定样本 + 回归断言 + 报告）**

## 1. 背景：导入可靠性 = 可比指标

Plotline 12 地点 TikTok 公开测试把「导入可靠性」变成行业可比指标：

| 竞品 | 机制 | 实证结果 |
|---|---|---|
| **Plotline** | 分享表 → 增长地图（collect-first） | 12 地点**全命中** |
| **Wanderlog** | 导入直接进行程（trip-only） | 同测试**漏 2/12** |

我们的五通道导入（note / social / email / link / screenshot）**各有功能测试，
但无统一召回基线**——不知道「十个地点丢几个」，也就无法与竞品横向对比、
无法在规则改动时防回归。

## 2. 样本设计（固定、公开、零凭证、纯规则）

`backend/tests/import_recall_samples.py`：

| 样本 | 通道 | 已知地点数 | 形态 |
|---|---|---|---|
| `NOTE_ZH` | note_import（中文攻略） | 10 | 序号 + 地点 + 描述（西湖/灵隐寺/龙井村/楼外楼/西溪湿地公园/河坊街/南宋御街/雷峰塔/杭州动物园/千岛湖） |
| `NOTE_EN` | note_import（英文攻略） | 10 | 序号 + 地点 + 描述（Sensoji Temple/Shibuya Crossing/…/Ginza） |
| `SOCIAL_ZH` | social_import（中文 caption） | 6 | 口语噪声 + emoji + 链接（山外山菜馆/灵隐寺/in77 商场/西湖/河坊街/南宋御街） |
| `EMAIL_ZH` | email_import（中文预订邮件） | 3 | 酒店 ×2 + 门票 ×1（杭州西湖大酒店/灵隐寺/西溪宾馆） |

**匹配口径**：归一化（去空白 + 小写）后相等或双向子串包含，长度容差 ±4 字
（防「杭州西湖大酒店」误命中「西湖」式偏颇）。同 Plotline 测试的可复现代理。

但条目级误判是已知噪声，记录待后续评估。

## 4. 回归断言设计（`backend/tests/test_import_recall.py`，7 例）

| 断言 | 阈值 | 理由 |
|---|---|---|
| 中文攻略召回 | **≥ 0.9** | 防回归；基线 1.0，留 1 个容差 |
| 中文攻略元数据 | 价格/时长精确 | 召回之外的字段级防回归 |
| 英文攻略召回 | **≤ 0.3**（上限） | 已知差距 0.0；上限断言防「候选爆炸式虚假召回」——英文规则未实现时高召回意味着误命中，需核查而非庆祝 |
| 社交 caption 召回 | **≥ 0.9** | 防回归；基线 1.0 |
| 社交链接剥离 | 链接不进候选 + 平台识别 | 敌意/噪声输入处理防回归 |
| 邮件候选召回 | **≥ 0.9** | 防回归；基线 1.0 |
| 邮件条目结构化 | 名称/确认码/金额/币种/日期 | 条目主链路防回归 |

**英文差距的诚实处理**：0/10 记入报告与代码注释，不设「通过」指标；未来若
落地英文地名收尾词表，把上限断言升级为下限阈值。

结论：中文场景召回与 Plotline 同级（无漏检）；**英文场景是明确差距**——
Wanderlog 漏 2/12 仍有 83%，我们 0/10。这是国际化的导入短板，建议登记为
后续行动项（英文地名收尾词表 / 英文规则启发），本任务只立基准不扩规则
（铁律 1：只做计划内任务）。

## 7. 遗留与后续（记入 checkpoint issues）

1. **英文攻略召回 0/10 是明确差距**：可与国际化 7 语种（中英韩西马来法德）联动，
   立项「英文/多语种导入规则」（收尾词表扩展或轻量启发），本基准即为验收门
2. **EMAIL 条目级误判**：`_ROUTE_RE` 把 `XX9988` 式订单号当航班 → «航班 XX9988»，
   空 activity 条目噪声——候选无影响，条目链路待后续评估
3. **link/screenshot 通道**：二者汇入 note_import 管线（深度抽取 / OCR 文本 →
   parse_note），本基准的 NOTE_ZH 即覆盖其解析段；OCR 真实图识别不在零网络
   基准内（沿用 test_screenshot_import 的 smoke test 策略）
