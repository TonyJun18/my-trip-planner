## 一、项目定位（一句话）

**把「多 Agent 协作生成行程」做成生产级工程的智能旅行应用**——不是调 LLM 的 demo，而是回答了这类系统真正难的问题：LLM 输出不可信时，怎么用 编排层代码 + 强校验 + 质检闭环 + 确定性规则兜底 让多 Agent 稳定、可靠、可测试地产出结构化业务数据。

差异化主张：**规划层做深**（透明、可修订、可验证、诚实预算），不与 OTA/巨头拼预订层。

## 四、差异化资产（值得对外讲的点）

1. **编排层补位哲学**：餐饮搜索由编排层代码补齐（不依赖 prompt 自觉）——「LLM 只做理解与编排，数学和事实交给代码」
2. **修订的一等公民设计**：AI 出 diff、代码执行、修订后重校验、diff 预览 + 质检 trace（已写成文章 04/05）
3. **确定性规则库体系**：DrivingGate / TimeGate / Plan B / 预算校准 / 体力（排队中）——零 LLM 成本、可单测、诚实标注 basis
4. **可测试性当一等公民**：409 测试靠 FakeLLM 替身零 token 全绿，是同类项目极少见的
5. **无人值守夜间开发流水线本身**：竞品分析 → 差距补功能 → 测试 → 分支提交的闭环（README 已声明）
6. **强校验 + 失败自纠正 + 容错工程**（文章 01/02/03 的差异化主题）

- **工程化程度**：极高（409 测试全绿、分层清晰、容错完备、诚实标注体系）——远超普通 demo/PoC 水平。
