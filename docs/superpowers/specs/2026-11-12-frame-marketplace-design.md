# 旅拍相框市场（Frame Marketplace）设计

日期：2026-11-12
状态：已获用户批准（方案 B：前端 Canvas 渲染）
工作流：superpowers-openspec-execution-workflow（阶段 1 产物）

## 1. 背景与目标

「随行」的旅行规划主线已完成，本功能是第一个创收模块：把**旅途中的每日打卡**变成可售卖的产品。

用户价值：行中每天打卡后，把当天照片 + 路线轨迹 + 趣事一句话合成为精美「打卡卡」，一键导出成品图 + AI 配文，手动发布到小红书/朋友圈。

商业价值：免费基础相框拉新留存，付费模板包（兑换码一次买断）创收；照片全程不离开用户设备，隐私是强卖点。

### 已确认的需求决策

| 决策点 | 结论 |
|---|---|
| 发布方式 | 生成成品图（叠加行程地图轨迹）+ AI 配文，用户手动发布（无自动发布副作用，与 xhs-note 立场一致） |
| 商业模式 | 免费 + 付费模板包，一次买断 |
| 收款 | 兑换码模式（外部平台如爱发电售卖，站内兑换） |
| 成品图形态 | 单日打卡卡（Phase 1）+ 整程总结图（Phase 2，同一 change 内） |
| 配文 | AI 生成（LLM 主路径 + 模板兜底），复用 xhs 双路径架构 |

### 实现方案（已批准）

**方案 B：前端 Canvas 渲染。** 成品图在浏览器合成，照片用本地 File API 读取不上传；后端只管模板目录、兑换码/权益、AI 配文、站点轨迹坐标数据。轨迹不嵌地图瓦片（CORS 无法导出），用站点坐标手绘风格化路线（虚线 + 编号节点 + 地名标签），零外部依赖。

备选方案 A（后端 Pillow 渲染 + 照片上传）被否决：需要照片存储基础设施、隐私顾虑重、工作量大；仅在未来做「高清印刷纪念册」时再演进。

## 2. 数据模型

新建 `backend/app/models/framemarket.py`，4 张表：

```
FrameTemplate        相框模板目录（代码内置种子数据，非用户数据）
  id, slug(唯一), name, tier(free/paid), theme(文艺/搞笑/极简/手账),
  layout_config(JSON: 槽位数量/轨迹样式/水印字段), price_cents, active

FramePack            模板包（售卖单元，1 包 N 套模板）
  id, slug(唯一), name, description, template_slugs(JSON), price_cents, active

RedemptionCode       兑换码
  id, code_hash(唯一, SHA-256), pack_slug, status(unused/used/revoked),
  redeemed_by, redeemed_at, note(来源渠道备注)

FrameEntitlement     用户权益（兑换后落库）
  id, user_id, pack_slug, redeemed_at；唯一约束 (user_id, pack_slug)
```

要点：
- 模板本体是**前端渲染器可执行的 JSON 配置**（槽位、配色、字体、轨迹风格），后端只存目录与价格；渲染逻辑在前端 canvas 模块
- 兑换码**只存哈希不存明文**——明文码由一次性脚本输出供上架，不落库
- 权益幂等：重复兑换同一包返回已解锁，不报错；一期不做退款/过期

**不做**：支付订单表、照片存储、模板热更新后台（种子数据 + alembic 迁移）。

## 3. API 设计

新路由文件 `backend/app/api/v1/frames.py`，挂 `/api/v1`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/frames/catalog` | 模板目录（免费+付费全部，带 `locked` 标注；免登录可看，用于商店页） |
| GET | `/frames/entitlements` | 我的已解锁包列表（需登录） |
| POST | `/frames/redeem` | 兑换码换权益（需登录，幂等；未命中 404，已用 409，吊销 410） |
| GET | `/trips/{trip_id}/frames/{day_id}/data` | 单日卡数据投影：当日打卡站点坐标/名称/天气/趣事/日期（owner） |
| GET | `/trips/{trip_id}/frames/summary/data` | 整程总结图数据投影（owner，Phase 2） |
| POST | `/trips/{trip_id}/frames/{day_id}/copy` | AI 配文生成（channel=xhs/moments，`source` 标注 llm/template） |

要点：
- **数据投影与渲染分离**：后端只出结构化数据，渲染在前端；未购买模板仅能预览水印缩略图，后端不下发渲染素材
- **趣事存储**：站点趣事用现有 `Stop.notes`（尊重现有受邀者编辑权模型）；`TripDay` 新增可选 `day_note` 字段（当日一句话总结）
- 免费模板零权益校验；未登录可浏览目录，兑换时引导注册（复用现有 auth）

## 4. 前端渲染器

新增 `frontend/src/frames/`：

```
frames/
├── renderer.js        # canvas 绘制管线
│   ├── drawBackground   模板底色/纹理/装饰
│   ├── drawPhotoGrid    槽位布局（cover 裁切 + 拍立得白边等槽位风格）
│   ├── drawRoute        站点坐标球面投影 → 虚线路径 + 编号节点 + 地名标签
│   ├── drawMeta         日期/城市/天气/趣事水印
│   └── drawLockWatermark 未购买模板的预览水印
├── templates.js       # 模板注册表（与后端目录 slug 对齐）
└── export.js          # canvas → PNG 下载 + 配文复制到剪贴板
```

页面与入口：
- **模板商店页**（`FrameStoreView`，路由 `/frames`）：免费/付费分栏，示例小样用真实行程数据渲染，付费包带兑换码入口
- **单日卡生成器**：入口在今日视图打卡完成态 + 行程详情每日一行的「生成打卡卡」；流程：选模板 → 本地选照片 → 填/改趣事 → 实时预览 → 导出 PNG + 复制配文
- **整程总结图**：入口在行程详情定稿态「生成旅程相册图」（Phase 2）

技术决策：
- 导出尺寸固定 3:4（1242×1656，小红书/朋友圈首选比例），DPR 感知保证清晰度
- 照片只在内存处理（`createImageBitmap`），不落 localStorage，页面关闭即消失

## 5. 整程总结图（Phase 2）

- 布局：封面头图槽位 + 按日分区小图槽位 + 全程手绘轨迹总览（多日串联）+ 天数/站点数统计水印
- 数据源：`/frames/summary/data` 聚合各日投影；只生成有打卡数据的日期，空日自动跳过（诚实返回，与 journey 投影哲学一致）

## 6. AI 配文

- 新服务 `frame_copy_service.py`：输入 = 当日打卡站点名 + 用户趣事 + channel；LLM 主路径 + 规则模板兜底（`source: llm/template` 诚实标注），参照 `story_service` 模式
- 输出：标题 + 正文 + 话题标签，前端一键复制；发布动作在用户手里，接口无自动发布副作用

## 7. 错误处理（全部不阻断主流程）

| 场景 | 处理 |
|---|---|
| LLM 配文失败 | 模板兜底；兜底也失败 → 用户趣事原文 + 固定话题 |
| 照片加载失败（损坏格式） | 槽位显示占位图，可继续导出 |
| 兑换码不存在 | 404「兑换码不存在」 |
| 兑换码已被使用（他人） | 409「该码已被使用」；**同一用户重复输入自己已兑换的码 → 幂等 200 返回已解锁** |
| 兑换码被吊销 | 410，文案明确区分便于对账 |
| 当日无打卡数据 | 生成器入口置灰，提示「先去打卡」 |

## 8. 测试策略（TDD）

- 后端（FakeLLM，不耗 token）：兑换幂等/错码/重放；权益隔离（用户 A 的码可被 B 兑换但只解锁 B）；数据投影只含 checked 站点；配文降级链
- 前端：渲染器纯函数部分（槽位布局计算、坐标投影、水印换行）vitest 单测；canvas 绘制人工验证
- 现有 453 个测试全绿为验收底线

## 9. 交付节奏

1. **Phase 1**：数据模型 + 兑换权益 + 目录 API + 前端渲染器 + 单日卡生成器 + 模板商店（2 套免费 + 2 个付费包各 3 套）
2. **Phase 2**：整程总结图 + AI 配文接入
3. **工具**：`scripts/gen_codes.py` 一次性脚本——生成明文码列表（供上架）+ 哈希入库，明文不落库

## 10. 范围边界（一期不做）

- 不做支付直连/订单系统（兑换码模式起步，资质就绪后可平滑升级官方支付）
- 不做照片上传与云端存储
- 不做模板后台热更新
- 不做自动发布到任何社媒平台
- 不做退款/权益过期
